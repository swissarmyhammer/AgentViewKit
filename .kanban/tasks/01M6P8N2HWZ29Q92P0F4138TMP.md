Requested by Testudo (testudoapp-bf, 2026-11-05) for its multi-file inspector capture (Testudo ^z3xr560). Rule: a kit feature needs no host glue.

## Today (AVK 79c0c2d7)
- `AttachmentInspectorMode.host(Binding<AgentAttachmentSelection?>)` holds one value; each tap replaces it.
- `InspectorSelectable` (AttachmentView.swift) and `ImageView.select(data:)` use a plain `.onTapGesture` that ignores modifiers.
- AVK's `InspectorSelection` holds a single attachment.

## What
- Follow EK's selection model, as chat rows do: a plain click selects one, Command-click adds or removes one, Shift-click extends the range in transcript order.
- **Host API:** an ordered list of selections, e.g. `.host(Binding<[AgentAttachmentSelection]>)`. Keep it ordered so AttachmentInspector folds them in selection order. AVK's own `InspectorSelection` holds the same list.
- AttachmentInspector shows the selection folded (it already takes `[Attachment]`, and Mixed rows already work).
- **Accessibility:** each attachment exposes named actions for select, "Add to Selection" and "Extend Selection", so tests and VoiceOver can do what Command- and Shift-click do. Tests drive these actions, never the mouse.
- **Breaking change:** replacing the single-value `host` binding breaks Testudo. Grep the KVK, SVK and Testudo origin mains first. No shim: send testudoapp-bf the local SHA and the new API shape before pushing, and pair the pushes.
