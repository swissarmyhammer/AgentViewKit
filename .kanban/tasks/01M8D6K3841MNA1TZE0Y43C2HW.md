`StatusLineContent` (Sources/AgentViewKit/StatusLine/StatusLineView.swift) sets `.accessibilityElement(children: path.isEmpty ? .ignore : .contain)`. For a root session the whole line is one StaticText, so the modules that take a tap (`agent-status-line-<module>`) are not elements: VoiceOver cannot press them, and a UI test cannot avoid them. `ThreadStatusHeader` (Sources/AgentViewKit/Thread/ThreadStatusHeader.swift) has no element for its glass.

## What
- [ ] Each module that takes a tap is an accessibility element also with no crumbs: the button trait, the identifier `agent-status-line-<module>`, the frame of the module text, its help as its value. A press runs the same status line action as a tap.
- [ ] The line keeps its identifier `agent-status-line`, its label (the plain text of the line) and its value (the full path of the working folder).
- [ ] The glass of `ThreadStatusHeader` is one container element with the identifier `agent-status-header` and the frame of the glass, inset included.

## Acceptance Criteria
- [ ] In the accessibility tree of a root session header, `agent-status-line-directory` is a button inside `agent-status-line`, and a press calls the status line action of `directory` one time.
- [ ] `agent-status-header` has a frame that contains the frame of `agent-status-line`.
- [ ] VoiceOver still reads the line with its label and value.

## Tests
- [ ] A hosted test in IntegrationTests (next to the status line hosted tests) for the 3 criteria, written first (RED on main).
- [ ] Headless unit tests where possible. `swift test` passes with 0 failures and 0 warnings. The full IntegrationTests run passes (a screen slot).
