## What
The status line `directory` module shows `/U/w/L/M/i/D/Agents` for `~/Library/Mobile Documents/iCloud~testudo~app/Documents/Agents`. Finder shows `iCloud Drive › Testudo › Agents`. The Testudo user says the text is cryptic. This replaces the 1-letter rule of D194 (f). Testudo changes the decision text (Testudo card ^6jt64qs).

Files:
- `Sources/AgentViewKit/StatusLine/StatusLineRenderer.swift` (`StatusLineDirectory.parts` near line 419-500, `fishStyle` near line 494, the home from `NSHomeDirectory()` near line 120).
- `Sources/AgentViewKit/StatusLine/StatusLineModules.swift` (`fishStylePwdDirLength` default near line 132).
- The view of the module (for `.help` and the accessibility value).
- `Tests/AgentViewKitTests/StatusLine/StatusLineDirectoryTests.swift` (or the file that has the directory tests now).
- ScreenshotTests status line gallery fixtures (`ScreenshotTests/Tests/ScreenshotTests/StatusLineGalleryFixtures.swift`).

Work:
- [ ] The default parent parts are whole names. The default `fishStylePwdDirLength` is 0. The option stays.
- [ ] Each part is its Finder display name, from an injectable resolver (the default uses `FileManager.displayName(atPath:)` or `localizedName`). `~/Library/Mobile Documents/com~apple~CloudDocs` shows as `iCloud Drive`. A container `~/Library/Mobile Documents/<container>/Documents` shows as `iCloud Drive › <container display name>`. The separator is ` › `, as in Finder.
- [ ] The home is the real home of the user (`getpwuid(getuid())`), not `NSHomeDirectory()` (in a sandboxed app that is the container folder). The home shows as `~`.
- [ ] A long path removes whole names from the middle and puts one `…` there. It keeps the last folders whole. It never shows 1 letter for a name.
- [ ] The full POSIX path is the tooltip (`.help`) and the accessibility value of the module. Gallery fixtures show an iCloud container path and a long path.
