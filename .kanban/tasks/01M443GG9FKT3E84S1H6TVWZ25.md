## What
`ACPDemoSession` (`Sources/DemoSupport/ACPDemoSession.swift`) calls `AgentProcess(command:)` with no arguments. The default subcommand of `acp-agent` is `run` (`AcpAgentCommand` in FoundationModelsACPAgent). Thus the agent does not speak ACP. Source: update.md §9.1.

`ACPDemoSession` calls `AgentProcess` directly, not through `ProcessLauncher`, so a fake launcher cannot record the arguments. Put the decision in a pure function.

- [ ] Add a pure function `DemoLaunchOptions.agentArguments(for command: String) -> [String]` in `Sources/DemoSupport/DemoLaunchOptions.swift`. It gives `["acp"]` for `acp-agent` (also when the command is a path that ends in `acp-agent`), and `[]` for other commands.
- [ ] `ACPDemoSession` passes `arguments: DemoLaunchOptions.agentArguments(for:)` to `AgentProcess`.
- [ ] There is no `--acp` flag. Change the tests in `Tests/AgentViewKitACPTests/ACPThreadActionsTests.swift` that use `--acp`.
- [ ] Make sure that the README text for `--agent-command` is correct (`README.md`), and run `Scripts/check-readme.sh`.

## Acceptance Criteria
- [ ] `agentArguments(for: "acp-agent")` and `agentArguments(for: "/usr/local/bin/acp-agent")` give `["acp"]`; `agentArguments(for: "other-agent")` gives `[]`.
- [ ] No test or document uses the `--acp` flag.
