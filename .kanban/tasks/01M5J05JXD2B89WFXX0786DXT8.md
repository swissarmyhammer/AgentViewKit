title: AVK The built-in attachment inspector drops an outer host top bar from the thread's safe area
---
Found while working ^ph0m0hf (2026-10-22), measured offscreen in the AVK hosted harness.

Shape: `AgentThreadView(session:connection:)` in the default `.builtIn` attachment inspector mode, wrapped by the host in `.safeAreaBar(edge: .top) { 24 pt bar }`. The same happens with `.safeAreaInset(edge: .top)`, with a `.frame(maxWidth:maxHeight:)` in between, and inside a `VStack`.

Observed (borderless 480x800 harness, thread with a connection header and one notice):
- The host bar is at y 0-24. The AVK `AgentInfoHeader` is at y 8-40, so it is drawn UNDER the host bar (overlap).
- The `conversation-list` `NSScrollView.contentInsets.top` is 131, the AVK top bar alone. The expected value is 155 (24 + 131).
- With `.agentAttachmentInspector(.host(...))`, the same host gives header y 32-64 and inset 155. Correct.
- So the cause is probably the `.inspector(isPresented:)` that `ThreadAttachmentInspector` applies in `.builtIn` mode (`attachmentInspector(selection:)`, `Sources/AgentViewKit/Attachments/AttachmentInspectorMode.swift`). It does not pass the outer safe-area bar inset on to the thread content.

Red test, already in the tree (uncommitted at the time of filing): `ThreadBarInsetHostedTests.theTopInsetOfAThreadUnderAHostBarCountsTheHostBar` in `Tests/AgentViewKitTests/Thread/ThreadBarInsetHostedTests.swift`.

Work:
- Make the thread honor an outer top bar or inset in `.builtIn` mode. The header goes below the host bar, and the list's top inset counts the host bar.
- The test above goes green. The host-mode, plain and split-view shapes in the same suite stay green, and so do the ThreadTopBar/ThreadBottomBar tests.
