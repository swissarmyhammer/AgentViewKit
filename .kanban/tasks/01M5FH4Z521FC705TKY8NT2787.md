Source: the user, 2026-10-21. The test windows take the focus and make the computer unusable. Research report: the window-less test research in this session (probes in the scratchpad `probe5/`).

Cause: `HostedViewHarness` (Sources/AgentViewKitTestSupport/HostedViewHarness.swift, about lines 145-151) makes a `.titled` `KeyableWindow` and calls `makeKeyAndOrderFront`. AppKit moves a titled window onto a screen (`constrainFrameRect(_:to:)`), so the off-screen origin does not hold. The harness sets the activation policy `.accessory`.

Do (in the harness, one place):
- Make `KeyableWindow` with `styleMask: [.borderless]`. Keep the `canBecomeKey` override.
- Remove `makeKeyAndOrderFront`. Never order the window in.
- Set `NSApplication.shared.setActivationPolicy(.prohibited)` before the first window.
- Set `window.colorSpace = .sRGB`.
- Keep `AXEnhancedUserInterface`, `sendEvent`, `makeFirstResponder` and the accessibility reads.
- For SwiftUI focus and key tests (`@FocusState`, `.onKeyPress`): the keys arrive after one run loop pass that does not wait, `RunLoop.main.run(mode: .default, before: .distantPast)`. The user permits this one pass (2026-10-21). Put it in one harness function (for example in `render()` or a new `settleFocus()`), not in each test. No clock, no sleep, no poll, no retry, no time limit.
- Check every other place in Sources/AgentViewKitTestSupport and Tests that makes a window, orders a window in, or activates the app (`orderFront`, `makeKeyAndOrderFront`, `activate`, `NSApp.activate`, `.regular` policy), and change it the same way.
- Check that the window-cache pixel tests (`ContentEdgeHostedProbe`, `GlassRenderProbeHostedTests`, `EditorThemeViewsTests`) still draw in the hidden window.

Acceptance:
- A guard test: after a hosted test mounts a view, no window of the process is visible (`NSApp.windows.allSatisfy { !$0.isVisible }`), no window is key, and `NSApp.isActive` is false.
- A structure test: no test source and no test-support source calls `makeKeyAndOrderFront`, `orderFront`, `orderFrontRegardless` or `NSApp.activate`, outside an allow list that is empty or has a reason for each entry.
