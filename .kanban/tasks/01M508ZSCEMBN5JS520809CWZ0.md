Bad test found in the T3 full run (^pvje3w3). The T3 changes did not touch this test. Not fixed: the fix needs a decision of the step owner.

- Test: `SessionTranscriptViewHostedTests.theScrollAnchorsSeeTheRowKeyOfEachRowInView()` in Tests/AgentViewKitTests/Thread/SessionTranscriptViewHostedTests.swift (changed by ^66f5w2n, commit 5ea918c).
- Wait: `await ObservationWait.until { anchors.visibleIDs.count == model.transcript.count }`. Only `ConversationView.list` -> `.onScrollTargetVisibilityChange` -> `ScrollAnchorManager.noteVisible` sets `visibleIDs`. SwiftUI calls that action on a later update. In a full run, SwiftUI can send no report at all: in the T2 full run (^66f5w2n) `visibleIDs` was `[]` after 12.8 s of `pump(until:)`. With no time bound, the wait never ends.
- Effect: the test holds `HostedTestLock.shared` (trait `.hostedSerially`). Each other hosted test waits for the lock, so all hosted tests stop, at 0 % CPU. In the T3 log the hosted tests got the lock in the order of their start lines (3034, 3036, 3041, 3045, 3053, 3064 passed); the next start line, 3069, is this test, and no hosted test passed after it.
- Probable cause (not proved): the harness window is at an off-screen origin. When the window server reports the window as occluded before the list lays out (more probable under the load of a full run), SwiftUI does not compute the scroll target visibility. In a filtered run the test ends before that report, so a filtered run cannot show the failure.

Decision needed (not in the plan), one of:
1. A direct call that makes SwiftUI send the visibility report (for example a display pass of the window), if one exists and is deterministic.
2. A harness change that keeps the window visible to SwiftUI (occlusion state).
3. A change of what the test checks (for example the scroll target ids of the rows, from the accessibility tree), so that it does not wait for the report.

Other tests that wait for the same report use `pump(until:)` with a time bound (ConversationViewHostedTests, ThreadMinimapViewHostedTests, AgentCommandScopeHostedTests). They cannot hang, but they can fail for the same cause. Do the same change for them when the step owner decides. Write all text in STE. #mail-step-7
