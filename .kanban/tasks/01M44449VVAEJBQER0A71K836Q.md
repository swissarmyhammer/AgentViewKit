## What
After the kit session model is gone, the kit copies of ACP value types have no use. The views use the ACP types directly. Source: update.md §4.5 (row 5). Owner rule (2026-10-06): each view binds directly to the observable model of FoundationModelsACPClient and reads the ACP values that the model objects hold. No kit type copies an ACP value, and no view converts a model value to a kit value.

- [x] Delete from `Sources/AgentViewKit/Model/`: `ThreadState.swift`, `SlashCommand.swift`, `ConfigOption.swift`, `ContextUsage.swift`, `JSONValue.swift`, `PatchField.swift`, `WireValueEnum.swift`, `ContentBlock.swift` (the kit content block; the content views take the ACP `ContentBlock` after the content binding task), and the kit `StopReason`, `ToolKind`, `ToolCallStatus`, `PlanEntry` and `AuthMethod` types. Delete `Sources/AgentViewKit/Sessions/SessionSummary.swift`.
- [x] Keep a type only if a view needs a value that ACP does not define (for example the composer draft `UserInput`). Record each kept type and its reason in `Docs/decisions/acp-client-kit.md`.
- [x] Change the remaining callers to the ACP types (`JSONValue`, `StopReason`, `ToolKind`, `ToolCallStatus`, `ContentBlock`, `PlanEntry`, `AvailableCommand`, `SessionConfigOption`, `AuthMethod`, `SessionInfo`), read from the model objects at the time of the body.
- [x] Delete the tests of the removed types. Add `PatchField`, `WireValueEnum` and `SessionSummary` to `RemovedVocabularyTests`.
