## What
After the kit session model is gone, the kit copies of ACP value types have no use. The views use the ACP types directly. Source: update.md §4.5 (row 5). Owner rule (2026-10-06): each view binds directly to the observable model of FoundationModelsACPClient and reads the ACP values that the model objects hold. No kit type copies an ACP value, and no view converts a model value to a kit value.

- [ ] Delete from `Sources/AgentViewKit/Model/`: `ThreadState.swift`, `SlashCommand.swift`, `ConfigOption.swift`, `ContextUsage.swift`, `JSONValue.swift`, `PatchField.swift`, `WireValueEnum.swift`, `ContentBlock.swift` (the kit content block; the content views take the ACP `ContentBlock` after the content binding task), and the kit `StopReason`, `ToolKind`, `ToolCallStatus`, `PlanEntry` and `AuthMethod` types. Delete `Sources/AgentViewKit/Sessions/SessionSummary.swift`.
- [ ] Keep a type only if a view needs a value that ACP does not define (for example the composer draft `UserInput`). Record each kept type and its reason in `Docs/decisions/acp-client-kit.md`.
- [ ] Change the remaining callers to the ACP types (`JSONValue`, `StopReason`, `ToolKind`, `ToolCallStatus`, `ContentBlock`, `PlanEntry`, `AvailableCommand`, `SessionConfigOption`, `AuthMethod`, `SessionInfo`), read from the model objects at the time of the body.
- [ ] Delete the tests of the removed types. Add `PatchField`, `WireValueEnum` and `SessionSummary` to `RemovedVocabularyTests`.

## Acceptance Criteria
- [ ] No source declares a type with the same name as an ACP type, except the kept types in the decision record.
- [ ] No source in `Sources/AgentViewKit/` has a function that maps an ACP value to a kit value of the same meaning.
- [ ] `swift test` and `Scripts/check-readme.sh` pass.

## Tests

- [ ] The hosted binding tests of the view groups pass with the ACP types (a model change shows in the view).
