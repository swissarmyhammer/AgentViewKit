## What
The kit keeps no copy of the pending requests. Source: update.md §3 (pending requests in the models), §4.6 item 3, §9.4 (permission comment wait).

- [ ] `PendingRequestsHost` (`Sources/AgentViewKit/HumanInTheLoop/PendingRequestsHost.swift`) reads `SessionModel.pendingPermissions` and `pendingElicitations`, and `ConnectionModel.pendingElicitations` for request-scoped elicitations (for example during `auth/login`).
- [ ] `PermissionView` calls `selectPermission(_:option:)` and `cancelPermission(_:)`. `ElicitationView` and `ElicitationURLConsentView` call `acceptElicitation(_:content:)`, `declineElicitation(_:)` and `cancelElicitation(_:)` on the model that owns the request.
- [ ] Remove the fixed 50 ms wait before a permission comment goes out as a prompt. Note: `selectPermission` is synchronous and returns before the response frame is written. Send the comment only after the response frame is on the wire (for example, await the next turn of the connection write queue, or a signal from the model). If no reliable signal exists, keep the order with the smallest safe mechanism and record the gap for FoundationModelsACPClient.
- [ ] Remove the mirror code of the pending requests from `ACPThreadSource` and the reply code from `ACPThreadActions`.

## Acceptance Criteria
- [ ] A permission request shows a card; a selected option goes to the agent and the card goes away.
- [ ] With a comment, the permission response frame comes before the `session/prompt` frame of the comment, in every run.
- [ ] A request-scoped elicitation during login shows in the connection-level host, and goes away when the login request ends.
- [ ] No code in the kit keeps a list of pending requests.

## Tests
