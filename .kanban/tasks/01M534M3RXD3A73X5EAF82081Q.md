## Design
- Data: `WithdrawnRequest` (id, request, reason), `SessionModel.withdrawnRequests`, `ConnectionModel.withdrawnRequests`, `dismissWithdrawn(_:)` (ACPClient fdd66eb, which card 39 brings in).
- `DeckCards` shows one row for each record of its model, in withdrawal order, above `DeckHeader`.
- Row text: "<title> was withdrawn: <reason>". With no reason: "<title> was withdrawn." The title is the same text as `PendingRequestSummary(request:)`.
- The row copies `NoticeBanner` (SessionNoticeBanner.swift): `SharedSymbol.information`, `editorTheme.tint(for: .info)`, glass, and a Dismiss button (`SharedSymbol.dismiss`) that calls `dismissWithdrawn(id)`.
- Identifiers: `request-deck-withdrawn-<id>` and `request-deck-withdrawn-dismiss-<id>` (RequestDeck.withdrawnIdentifierPrefix, withdrawnDismissIdentifierPrefix, identifier(forWithdrawn:)).
- The row stays until the user presses Dismiss. A new request does not remove it. The row takes no focus.
- Announcement: the row text one time, at `.default` priority.
- A deck with only rows shows the rows and the deck padding (this changes the empty-deck rule).
- Docs: change Docs/decisions/accessibility.md:52 and :84 (line 84 says that a withdrawn request gives no announcement).
- Known risk: after a reconnect, an old withdrawn record can appear in a new connection (an ACPClient gap).
