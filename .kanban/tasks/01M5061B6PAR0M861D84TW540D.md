title: A session request that comes at once after the session/new or session/resume result is pending on the session model (fixed in ACPClient 9cedcb9 and FoundationModelsACP fb55b2f; add the AgentViewKit test)
---
Found in mail step 7 T3 (^pvje3w3), G9. Not yet proven: confirm the cause first.

Probable cause: `ConnectionModel.resumeSession` (FoundationModelsACPClient 838bbad, `ConnectionModel+Sessions.swift`) calls `register(session, openedOver:)` only after the response and the replay. A session-scoped request (`elicitation/create` or `session/request_permission`) that the agent sends at once after the resume result goes to `ModelClient.awaitSessionElicitation` / the permission route. When the route runs before the register, `model?.session(for:)` gives `nil`, and the client answers `cancel`. The request is then never pending in the session model.

Where it showed: a first version of the G9 test resumed `DemoGallery.formElicitation` through `DemoAgent.makeInProcess(script: .gallery)` and waited for `session.pendingElicitations` to be not empty. In a parallel test run, the wait never ended (the log shows the `elicitation/create` request, but no later step of the test). In a run of that test alone, it passed. `InMemoryDemoACPAgent` sends the scripted requests in `afterRespondingToCurrentRequest` of `session/resume`, so the gallery sessions of the demo app can show no request in the same race. ACPAgent can also send an open question at once after a resume.

To decide: open the session model before the resume response is handled (client fix in ACPClient), or another rule. Add a fixed-order test: resume, the agent sends a session request at once after the result; the request is pending in the session model. #mail-step-7
