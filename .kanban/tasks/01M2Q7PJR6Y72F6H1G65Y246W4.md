## What
^ycgpyg6 added a local branch model (`AgentThread.branches`, `ThreadChange.addBranch` and `.selectBranch`) and `BranchNavigator`. The kit keeps the branches local. The sources do not know about a branch swap. This causes these problems:

- `SessionThreadSource` (Sources/AgentViewKitFoundationModels/SessionThreadSource.swift) maps the full transcript. It removes the items of entries that are not in the transcript, and it inserts the items of each entry again. After a swap, the next transcript change can put the old items back, or remove the items of the shown branch.
- The session transcript still holds the old answer. Thus Regenerate sends the prompt with the old answer in the context.
- `RouterThreadSource` adds a new user message (`user-N`) for each send. Thus Regenerate shows a second copy of the user message after the first one.

Make the sources agree with the shown branch:
- FoundationModels: rewrite the `Transcript` to the entries of the shown branch before a Regenerate send (the note on ^ycgpyg6 says that the checkpoint task did not add this).
- Router: use `RoutedSession.fork(workingDirectory:)` or the checkpoint path (Docs/decisions/checkpoints.md), or record the decision that the Router keeps the old context.
- A branch swap must not send `ThreadChange.clear`, because `.clear` removes the checkpoints and the branch sets.
