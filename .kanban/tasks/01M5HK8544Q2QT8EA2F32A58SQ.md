**Before you start:** the local checkout may be behind GitHub `main` (TestudoApp links `b4ce1eb`, and later commits exist). Pull first. On current `main`, `AgentCommandRegistration.register` writes the node with `registry.tree.merging(nil, by: .host, at: path)` and takes `groupsOff:`; the bug below is unchanged there.

## What

**The bug.** When SwiftUI rebuilds a chat (in Testudo: Swap Chat and View, ⇧⌘B, moves the chat to the other column), it makes a new `AgentThreadView`, which makes a new `AgentCommandScope` and a new `AgentCommandMount` at the SAME path `…/agentThread:<sessionId>`. SwiftUI makes the new mount (which registers the path) BEFORE it dismantles the old mount. `AgentCommandMount.dismantleNSView` of the old mount then calls `AgentCommandRegistration.deregister(at:from:)`, which runs `registry.tree.nodes.filter { $0.path != path }`. That removes the whole node at the path: the `.host` part that the NEW mount just wrote and the `.scope` part that the new `.commandScope(segment:subject:)` wrote. Nothing registers the path again until the new mount gets an `updateNSView`. Until then the resolution walk never reaches the path, so every `agent.*` command (Send ⌘↩, Cancel, Focus Composer, …) is gone from the menus, the keys and `CommandSystem.run`. Testudo measured this: for 1 s after ⇧⌘B, `registry.tree.nodes.contains { $0.path == chatPath }` stayed `false`, `registry.eligible(path: chatPath)` held no `agent.*` command, and `system.run(agent.focusComposer, clickedAt: chatPath)` returned `false`.

**The fix: owner token, using the pattern that EditorKit already has.** EditorKit solves the same race for its editor mount: `EditorScopeMountView` in `EditorSwiftUI/EditorContributor.swift` (EditorKit) uses `CommandSystem.mountHolders` (`ScopeMountHolders` in `EditorCommandsUI/ScopeMountHolders.swift`: `hold(at:by:)`, `isHeld(at:byOtherThan:)`, `release(at:by:) -> Bool`) with its coordinator as the holder. Do the same in `AgentCommandMount`. Do not write a second holder table in AgentViewKit.

All changes are in `/Users/wballard/github/swissarmyhammer/AgentViewKit/Sources/AgentViewKit/Commands/AgentCommandScope.swift`:

1. `AgentCommandMount.apply(to:)`, owned-scope branch (`if let scope`): after `AgentCommandRegistration.register(...)`, call `scope.system.mountHolders.hold(at: scope.path, by: coordinator)`. The `Coordinator` is a class, so it can be the holder.
2. `AgentCommandMount.updateNSView`: register again only when no newer mount holds the path. Skip the `register` + `hold` step when `scope.system.mountHolders.isHeld(at: scope.path, byOtherThan: context.coordinator)` is true. Otherwise an update of the old mount between the two events writes definitions that point at the OLD `AgentCommandTarget` over the definitions of the new one. Still write the anchors and the expanded-blocks store to the mount's own target (they only touch that target). `makeNSView` always registers and holds: the newest mount wins.
3. `AgentCommandMount.dismantleNSView`: call `AgentCommandRegistration.deregister` only when `registration.system.mountHolders.release(at: registration.path, by: coordinator)` returns `true`. The anchor and store cleanup stays as it is: it already checks identity (`target.anchors === anchors`).
4. `AgentCommandRegistration.deregister(at:from:)`: remove only the part that `register` wrote, `registry.tree = registry.tree.removing(.host, at: path)`, instead of filtering out every node at the path. `register` writes only `.host` (`merging(nil, by: .host, at:)`), and `ScopeTree.removing` drops the node when no owner stays. So the existing test `AgentCommandsTests.aSecondRegistrationDoesNotAddTheKeysAgain` (it expects `registry.tree.nodes.isEmpty` after deregister) still holds, and the deregister no longer erases the `.scope` part (live subject, layer flag) that `.commandScope` owns.
5. Update the doc comments of `AgentCommandMount` ("The teardown removes the registration…") and `deregister` to describe the holder rule. Do not cite line numbers.

The commands of the path read their model through the `AgentCommandTarget` that each definition captures (`AgentCommand.definition(of:for:)`). After the fix, the definitions at the path are those of the newest mount's target, and the old target is released when its view goes away.
