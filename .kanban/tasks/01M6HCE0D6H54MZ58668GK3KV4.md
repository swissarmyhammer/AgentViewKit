## What
This is the feedback of AgentViewKit, as a consumer of the session tree of FoundationModelsACPClient. For each item: what the views needed, what they did, and the proposed client API. The client session decides, and does the small items. The model is parent and child all the way down, so no item depends on a number of levels.

1. **The link of a tool call to its child is not observable.** Need: the `agents` row shows an "Open session" button as soon as the client reads the link. Did: `ToolCallEntry.childSession` is `@ObservationIgnored`, so `ToolCallChildLink` reads `entry.status` to be drawn again. Propose: make `childSession` observable.
2. **No tree lookups on `SessionModel`.** Need: find a session by id under a root, the path from the root, and the nearest ancestor that is not closed. Did: wrote `session(withId:)`, `pathModels` and `nearestOpenSession` in `Sessions/SessionTree.swift`, and test support has a copy of the lookup. Propose: `root`, `path` (`[SessionModel]`, root first), `session(withId:)` and `nearestOpenAncestor` on `SessionModel`.
3. **Siblings and descendants give entries, not models.** Need: the restore failure and the confirmation of each sibling in a dropdown. Did: walked up to the root and looked each id up again. Propose: put `isConfirmed` and `restoreFailure` in `SessionPathEntry`, or give a `status` there.
4. **`workState == .unknown` has three causes.** An unconfirmed child, a child that failed to restore, and a child with no state read differently to the user. Did: built `SessionStatus` (`Sessions/SessionStatusText.swift`) from `isWorkStateConfirmed`, `restoreFailure` and `workState`. Propose: `SessionModel.status` with these cases, and the same in `SessionPathEntry`.
5. **`needsAttention` counts the descendants.** Need: the session that itself waits (own request, or `requires_action`), to name it in a banner and to jump to it. Did: `waitsItself` on `SessionPathEntry`, `waitingDescendant` and `waitingElsewhere` (descendants, then ancestors, then siblings). Propose: `ownNeedsAttention` in the entry, and `firstWaitingSession(in:)` on the model.
6. **No rule for the controls of a child.** Need: when the composer works and when stop works. Did: a composer only for a root session, and stop only when the child is confirmed and `capabilities.cancel` is set (`SessionControls`). Propose: `SessionModel.canPrompt` and `canCancel` that the client already knows, so the views do not repeat the rule.
7. **A removed child is not an event.** Need: show the parent when the shown child goes away, and drop the child from menus. Did: read `isClosed` everywhere, and filter `children` with `!isClosed` in each menu. Propose: `openChildren`, and an observable removal (for example `removedAt`), or remove the child from `children` at once.
8. **Counts.** `pendingRequestCount` is the count of the session only. Need: the count of a branch for a collapsed crumb. Propose: `branchPendingRequestCount`.
9. **Naming.** `siblings` includes the session itself, which surprised the views; propose `siblingsIncludingSelf`, or document it at the call. `isReplaying` and `isReplayingHistory` are two names for near rules.
10. **No observable end of a resume.** Need: show the root again after a resume. Did: `onChange(of: root.isReplaying)`. Propose: a counter or a date that changes at each end of a resume, so the view needs no edge of a flag.
11. **Each read walks the tree.** `descendants`, `ancestors` and `siblings` build new arrays each time. A body of a big tree pays it at each draw. Propose: a cached value with a tree version that observation can track.
12. **Test seams.** Need: wait until a child exists, and a record of the wire trace of a connection to check it with `SubagentWireTraceValidator`. Did: a wait on `ObservationWait` with a tree search, and a recorder in the test support (`ScriptedChildWire`). Propose: a test helper in the client test support for both.
